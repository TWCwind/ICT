# 岗位图谱子系统 · 注意事项

> 早期版本记录的是「职途AI」登录模块（Spring Boot + MyBatis + MySQL + Redis）的开发约束，
> 与本仓库实际代码无关，已整体替换为当前 Python 子系统的注意事项。

## 1. 运行前

- 依赖较重：`requirements.txt` 含 `torch==2.3.1`、`faiss-cpu`、`transformers`、`sentence-transformers`，首次安装约 800MB+；
  未装依赖时 `job_api.py` 无法导入，接口层不可用。
- 首次使用语义检索会从 HuggingFace 下载 `paraphrase-multilingual-MiniLM-L12-v2` 模型（约 470MB），
  离线环境请预置模型目录并把 `model_name` 指向本地路径。
- 数据文件是 `structured_job_data.json`（50 条），不要改名为早期文档里的 `结构化岗位画像.json`；
  `job_database.py` 虽保留了旧路径兼容，但只把 `structured_job_data.json` 作为第一优先。

## 2. 数据层约束

- 存储是**单个 JSON 文件快照**：`_save_data()` 直接覆盖写，没有锁、没有并发控制、没有多用户隔离。
  多人同时写会互相覆盖，**生产使用前必须换数据库**（SQLite/PostgreSQL 均可）。
- 数据里含岗位名称、职责、技能要求等公开信息，不含个人信息；新增字段请同步更新 `job_schema.py`。
- 岗位路径数据写在 `job_graph.py` 的模块级常量里，与 `structured_job_data.json` 需要人工保持一致。

## 3. 接口与部署

- 端口默认 `8000`，与主工程后端（`01_ICT主工程/backend`，同样默认 8000）**冲突**，同时启动请改其一。
  主工程本地联调用 8000，本子系统建议用 `uvicorn main:app --port 8011`。
- 目前**无鉴权、无限流、无日志脱敏**：只允许本机或内网访问，不要把端口直接暴露公网。
- 若需接入 AgentArts 网关，MCP 服务在 `01_ICT主工程` 之外（`mcp_server/`），本子系统不提供 MCP。

## 4. 质量红线

- 提交前不要留下本机路径、临时文件（历史上曾把 `tmpclaude-0384-cwd` 这类记录本地绝对路径的文件提交进仓库，已清理）。
- 文档只写代码里真实存在的东西：技术栈、接口、目录结构必须能在仓库里指到具体文件，不允许把"计划中"写成"已实现"。
- 数据规模、验证状态要写实测数字（例如「50 条岗位、已验证数据加载层、未验证 HTTP 端到端」）。
